# Design

## Context

动机参见 `proposal.md` 的 Why；交互契约参见 `specs/fruit-catalog/spec.md`。

已检查 `AdminProductsView.vue`、全局 `styles.css`、前端 API、Element Plus 安装包样式入口及后端 `ProductService.status`：

- 当前上下架使用 `ElMessageBox.confirm`，确认框关闭后才发送请求，错误只显示在列表顶部，没有弹窗内提交状态。
- 三个商品/分类管理视图直接导入 `theme-chalk/el-message-box.css`。安装包官方 `es/components/message-box/style/css` 入口同时导入基础变量、input、button、overlay 等依赖；现有直接导入方式缺少这些依赖。截图中的透明内容区、原生按钮和过大图标与该缺失相符；未对当前运行页面做现场重现，实际修复结果需在应用阶段验证。
- 项目使用手工组件导入，没有自动导入插件，`main.ts` 只引入项目全局 CSS。
- `changeStatus` 已传递商品 ID、目标状态和版本，后端会校验分类、图片、启用 SKU、版本，并保存审计记录。API 已有管理员商品详情读取，足以处理重新核对状态。
- 主规范清单为空；沿用未归档商品变更的 `fruit-catalog` 路径，新增确认交互要求。应用本变更以现有商品模块已实现为前提，不改写或归档其他变更。

本次设计涉及共享样式入口和商品确认流程的技术决策，因此创建 design。

## Goals / Non-Goals

**Goals:**

- 将弹窗生命周期与请求生命周期统一管理，使提交、读取最新状态及关闭行为有明确约束。
- 将自定义外观限制在商品状态弹窗内，共享组件样式使用官方完整入口。
- 使用现有列表数据打开弹窗，以现有详情接口重新核对，保持服务端作为上下架规则的判断方。

**Non-Goals:**

- 不引入通用确认框框架、批量上下架、新的 UI 依赖或前端上架资格计算。
- 不重构全站设计系统，不增加后端错误类型、接口或数据库字段。

## Decisions

### 1. 使用受控的商品状态 Dialog

新增 `ProductStatusDialog.vue`，复用 Element Plus `ElDialog` 的遮罩、传送到 body、焦点约束和滚动锁定能力，内容及底部操作按商品场景定制。在 `AdminProductsView.vue` 中持有选中商品快照、目标状态、提交状态、错误和重新读取状态，组件负责呈现和发出明确事件。

采用受控 Dialog 的原因是提交失败时需要保留弹窗并重新读取商品。备选为继续 MessageBox 并使用 `beforeClose`，但富商品摘要、重新读取和状态控制会使函数式调用复杂；完全手写弹窗则增加焦点和滚动管理成本。

### 2. 选定“商品摘要卡片”布局

以下为设计值，应用阶段可为适配浏览器做微调，但必须满足规范中的可观察行为。

| 区域 | 设计 |
| --- | --- |
| 整体 | 桌面宽 460px，最大宽度为视口减去两侧 16px；白色不透明背景、16px 圆角、柔和阴影、约 24px 内边距；遮罩深色约 42% 透明度 |
| 标题 | 左侧 40px 柔色图标容器和 20px 标题；上架为绿色向上图标，下架为暖橙向下图标；右上角 18px 关闭图标，点击目标至少 44px |
| 商品摘要 | 64px 主图/占位、商品名称和分类；名称自然换行，摘要浅绿灰底；缩略图不裁切文字空间 |
| 状态 | 摘要下显示“已下架 → 已上架”或“已上架 → 已下架”，用文字和箭头共同表达 |
| 影响说明 | 14px 正文，约 1.6 行高；上架说明包含零库存显示售罄，下架说明包含推荐、列表、详情及收藏影响 |
| 底部 | 取消在左、确认在右，两者约 42–44px 高，间距 12px；取消白底描边，上架主按钮 `#28734a`，下架主按钮 `#a65a2e`，白色按钮文字 |
| 手机 | 至少两侧 16px 留白；内边距降为 20px；摘要可换行，操作按钮可均分宽度；短屏允许弹窗区域纵向滚动 |

上架文案：标题“上架商品”，说明“上架后，商品将在商城展示；库存为 0 时显示售罄。”

下架文案：标题“下架商品”，说明“下架后，商品将从商城推荐、列表和详情中隐藏，已有收藏会显示商品不可用。”

摘要中的商品名称使用普通文本插值，禁止 HTML 拼接。实际商品图片通过现有 `imageUrl` 处理；缺失或加载失败时显示占位。预览中的商品名沿用截图，“分类”是示意标签，不能视作现有数据。

备选为纯文本窄提示框，视觉轻，但操作对象辨识不如带主图的摘要卡片；此提案采用摘要卡片，无需用户另行决定布局。

### 3. 使用完整样式入口并限制覆盖范围

新增 Dialog、Button、Icon 等组件使用各自的官方 `element-plus/es/components/<name>/style/css` 入口，补齐传递样式；已有三个管理视图的 MessageBox 同样使用官方完整入口。确认当前版本可解析这些路径，生产构建验收包括直接访问管理页面。

商品 Dialog 自定义类采用 `.product-status-dialog` 前缀，覆盖传送到 body 后仍能命中的节点；避免依赖表格祖先和全局覆盖所有 `.el-*`。保持原有全局 `styles.css` 的后台色彩，并检查共享基础变量引入后账户和商城页面的字体、按钮没有意外改变。

备选为全量导入 Element Plus CSS，使用简单但扩大样式影响和产物体积；仅添加若干 CSS 变量则容易继续遗漏 overlay、button 或 icon 的几何样式。采用官方按组件入口。

### 4. 提交和重新读取采用明确状态

- 打开：保存商品 ID、名称、主图、分类、当前状态与 `version` 快照，目标状态固定为点击时的相反状态；已存在弹窗时拒绝重复打开。清空上次结果，将焦点放到取消。
- 空闲：确认、取消、关闭和 Escape 可用，遮罩点击无作用。按 Enter 仅执行当前焦点按钮，不设全局自动确认。
- 提交：同步设置忙状态后调用既有 `changeStatus`，禁用弹窗关闭及列表修改操作；使用 loading 图标及“上架中…”/“下架中…”文字。
- 成功：先关闭弹窗并给出页面内成功反馈，再调用现有 `load`。`load` 的错误属于列表读取失败，不能覆盖状态修改成功的结果。保持路由查询和已有越界空页处理。
- 已知拒绝：显示服务端 message，保留弹窗。`CatalogErrors.version` 返回 HTTP 409 / `VERSION_CONFLICT`，上架业务条件返回 409 / `CONFLICT`；按响应 code 区分。版本冲突禁止使用旧快照继续提交，提供“重新读取”；业务条件失败显示具体原因，可取消后编辑。
- 网络错误、超时或 5xx：结果可能不明确，禁用确认并提供重新读取。读取详情后，若仍不是目标状态则更新摘要和版本并要求再次确认；若已是目标状态则提示已更新并关闭、刷新，不重发相同目标。读取失败保留错误及取消，404 显示商品不可用并禁用确认；401 沿用既有登录失效处理。
- 重新读取：调用 `adminProduct(id)`；商品 ID 和本次目标保持不变，摘要和版本取最新详情。读取期间阻止并发确认和关闭，读取失败允许再次读取或取消。

备选为接口成功前更新列表状态，虽然响应快，但需要回滚且容易把失败操作显示为成功。此处只根据服务端成功结果刷新。

### 5. 验证以真实交互和产物构建为主

项目没有前端测试框架，不为本次界面变更引入框架。运行 `npm run typecheck` 和 `npm run build`，在独立测试商品上验收上下架、取消、连点、网络错误、上架条件拒绝、双窗口版本冲突和重新读取已达到目标状态。

使用 1280px 桌面、390px 和 320px 手机宽度及较短视口，检查长名称、缺图、遮罩、关闭图标、按钮、焦点和 Escape。检查实际页面和生产构建中的共享 MessageBox 入口，记录截图和结论。后端契约没有修改，不要求重复全量数据库回归；上下架真实联调覆盖现有规则。

## Risks / Trade-offs

- [共享组件基础样式影响其他页面] → 使用官方按组件入口及有前缀的覆盖；回归确认框和账户/商城关键页面。
- [传送到 body 后局部样式不命中] → 自定义类挂到真实弹窗节点，使用限定类名的全局规则，并在真实页面核对。
- [HTTP 409 同时用于版本和业务冲突] → 使用现有 `VERSION_CONFLICT` 与 `CONFLICT` 响应 code 区分，保留服务端 message，避免匹配中文字符串。
- [请求超时后修改可能已经成功] → 先读取最新状态再允许新的确认，禁止无核对重复提交。
- [成功刷新使原操作行离开列表] → 若触发元素已不存在，将焦点移至商品列表的可用控件或查询按钮。
- [提交期间阻止关闭降低即时取消自由度] → 请求沿用现有 10 秒超时，提供明确进行中反馈；结束后恢复取消。

## Migration Plan

1. 应用时增加组件和样式，接入现有商品列表流程，补齐已有 MessageBox 依赖入口。
2. 完成类型检查、生产构建和以上场景验收后发布前端；后端接口和数据库无迁移步骤。
3. 回滚时撤回本变更组件、调用和样式入口修改；保留其他商品模块实现及用户现有工作。
