# Proposal

## Why

商城已具备商品、订单、售后和库存闭环，但缺少能关联这些业务数据的智能咨询入口及后台治理能力。需要补齐有依据、可追溯、支持多轮对话的 AI 客服，并让管理员维护知识、配置模型、检查对话和衡量回答效果。

## What Changes

- 新增商城悬浮客服窗口、移动端对话界面、商品/订单上下文入口、流式回答、会话历史及有帮助/无帮助反馈；访客可咨询公共信息，本人订单/退款和跨设备历史要求买家登录。
- 采用在线 LLM＋RAG；水果知识、FAQ 和政策使用已发布知识，订单/物流/退款直接查询已授权业务服务。模型不可用时保留确定性的 FAQ、商品事实和本人订单/退款查询，并明确标记降级。
- 支持按预算、口味、月份和送礼需求推荐当前可售商品，展示真实商品卡片和回答依据；扩展商品甜度描述、应季月份、礼盒标记、适用场景，并同步商品知识。
- 新增知识文档的草稿、发布、停用、版本、索引状态和检索测试，避免编辑中的政策及失效商品继续参与回答。
- 基于 Spring AI 1.1.8 接入聊天模型、Embedding 与 RAG，匹配现有 Spring Boot 3.5；新增模型/API/提示词配置和连接测试，推荐百炼 `qwen3.7-plus`＋`text-embedding-v4`，API Key 加密保存且不回传明文；补齐经确认的配置删除，未引用版本永久删除、历史引用版本隐藏保留追溯、正在使用版本拒绝删除。
- 新增敏感词与拦截规则、输入及输出检查、请求限额；新建 AI 管理权限域，模型配置仅店主可操作，获授权店员可维护知识、查看脱敏记录及统计。
- 新增问答记录筛选、提问量趋势、高频问题、满意度、降级/失败/拦截统计，所有指标来自真实事件。
- **替代早期规划约束**：`fresh-fruit-ecommerce-platform` 中 AI 离线 ONNX＋模板、无在线模型配置的设计，由用户本次确认的在线 LLM＋RAG 和基础降级方案替代。历史制品保持作为历史记录，不把离线模板能力表述为 LLM 回答。
- 本次不扩展支付/物流供应商、换货业务、自动退款审批、自动下单、人工客服接管、图片/语音问答或外网搜索；AI 如实解释现有退货退款及模拟物流/退款规则。

## Capabilities

### New Capabilities

当前 `openspec-cn list --specs` 未发现主规范。以下均使用增量 ADDED 需求；沿用历史变更中已有的相关能力路径，避免重复命名。

- `ai-assistance`: 公共/买家问答、多轮上下文、流式生命周期、历史与反馈、业务查询和商品推荐。
- `ai-knowledge-management`: 知识版本发布、混合检索、可追溯依据、商品知识同步和可靠降级。
- `ai-model-configuration`: 模型适配、加密凭据、提示词与参数版本、连接测试、调用限额及超时。
- `ai-safety-governance`: 规则管理、输入输出拦截、数据最小化和受限业务工具。
- `ai-question-analytics`: 脱敏对话记录、事件统计、场景趋势、高频问题和反馈口径。
- `fruit-catalog`: 用于咨询和推荐的可选结构化商品资料及公开展示。
- `staff-access-control`: 新增 AI 权限域、店主模型管理边界和 AI 操作审计。

### Modified Capabilities

无已存在于主规范目录的能力可直接修改；上述新规范补充现有实现，且明确协调早期 AI 规划差异。

## Impact

- 前端：`App.vue`/商城页面、商品详情、个人中心、商品编辑、管理导航、店员授权、独立 AI API 与流式读取模块；复用 Vue 3、Pinia、现有状态/分页组件和 ECharts。
- 后端：新增 `ai` 领域，通过 Spring AI 的 ChatClient、EmbeddingModel 和 RAG Advisor 使用 OpenAI 兼容接口；复用目录、订单、售后、JWT、权限与审计服务；扩展商品 DTO/持久化和后台端点授权分类。
- 数据库：在当前 V8 后新增 Flyway 迁移，创建 AI 知识、索引、会话、消息、请求、反馈、配置、规则及统计事件表，扩展商品与权限约束；同步 H2 测试 schema，保留既有业务数据。
- 依赖与运行环境：使用 Spring AI 1.1.8 BOM、OpenAI 模型/向量 Starter 及 RAG 模块；新增模型接口和凭据加密主密钥配置，不引入 Redis、独立向量库、消息平台或本地 ONNX 权重。未配置 AI 时不实例化必需凭据的默认在线模型，商城仍可启动并提供基础降级。
- 交付：API 文档、模型配置说明、知识准备说明、数据库迁移及桌面/移动端验收记录。所有规划制品须经用户审核后，再显式启动 apply 编码。
