# Proposal

## Why

当前库存分散在商品编辑、订单发货和售后处理中，管理员缺少独立库存总览、采购入库、退供出库和盘点记录，难以完整追溯货物变化。本次补齐库存管理前后端，并统一库存变更入口，避免重复入库、重复扣减或直接覆盖账面库存。

## What Changes

- 新增管理员库存总览、库存流水、入库、出库、低库存预警及盘点页面和接口，复用 SKU 实物、预留和可售库存口径。
- 采购入库、退供出库采用多 SKU 简单单据：可保存草稿，管理员确认后立即生效，无独立审批。记录供应商名称、可选参考采购单号、数量和原因/备注，不建设供应商、采购订单、金额结算体系。
- 销售出库仅由商城订单发货产生；客户退货入库仅由既有售后验收产生。库存界面查询其来源并跳转相关业务，不提供独立手工重复过账入口。
- 低库存按启用 SKU 的可售数量严格低于正阈值判断，在后台预警列表和菜单数量提示中自动刷新；恢复到阈值即解除，不发送邮件、短信或站内通知消息。
- 盘点保存账面快照、实盘数量、差异和原因，确认后调整实物库存；不得低于预留库存，过期快照必须刷新复核。
- **BREAKING**：商品管理仅允许创建新 SKU 时设置初始库存，已有 SKU 的库存只读；阈值统一在库存模块配置。商品保存请求不得再调整已有 SKU 的库存或阈值，前后端契约和相关测试同步升级。
- 已生效单据和流水保留且不可直接修改；纠错通过新增盘点调整记录，保留原业务记录。
- 延续 SKU 整数计数、统一库存池，不引入批次、保质期、仓库调拨、线下销售或库存金额核算。

## Capabilities

### New Capabilities

- `inventory-control`: SKU 库存总览、采购入库、退供出库、订单与售后流水关联、盘点、阈值预警及管理员库存权限。
- `fruit-catalog`: 商品仅初始化新 SKU 库存，已有库存只读并阻止商品接口绕过库存作业。

上述路径沿用历史变更中的 capability 名称；`openspec-cn list --specs` 当前没有已注册主 spec，因此本次以 ADDED 增量描述行为，明确替代历史商品阶段的直接编辑库存规则，不修改其他历史变更或主 spec。

### Modified Capabilities

无已注册主 spec。本次改变已实现商品编辑行为，相关影响已在上文标为 BREAKING。

## Impact

- 后端：`inventory`、`catalog`、`order`、`aftersales` 及审计关联；新增管理员库存 API 和后续 Flyway 迁移，保留 V1–V5 和既有库存历史。
- 前端：管理员布局与路由、新库存页面/API 类型、商品编辑表单和提交契约；沿用 Vue 3、TypeScript 与既有交互风格。
- 验证：更新 H2 schema、商品库存相关用例，补充库存单据/盘点/权限/并发与订单售后回归，检查 MySQL 迁移和桌面/移动页面。
- 本变更仅为待审核规划，须在用户确认完整提案并另行要求应用后开始编码。
