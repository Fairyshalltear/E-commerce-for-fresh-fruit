# Proposal

## Why

当前前后端已具备账户鉴权、个人资料和地址功能，但商城首页和管理后台仍是占位页面，没有商品数据、分类、搜索或收藏功能。需要落实已确认的商品浏览与商品管理范围，为后续购物车、订单和库存模块提供一致的商品及 SKU 数据基础。

## What Changes

- 建设商城首页推荐、两级分类浏览、关键词/分类/价格区间组合搜索、分页与价格排序，以及商品图片、描述、产地、口感、储存方法、规格、价格和可售库存详情。
- 建设管理员商品分页列表、新增编辑、多 SKU 维护、图片上传与排序、上架/下架、逻辑删除，以及两级分类树增删改查、排序和启停。商品只归属二级分类。
- 首页采用管理员设置推荐标记和顺序，数量不足时补充最新上架商品；售罄商品仍可浏览并明确标记售罄。
- 建设买家收藏、取消收藏和个人中心收藏列表；下架、删除或分类不可用的收藏保留失效提示和取消入口。
- 每个 SKU 独立维护价格、实物库存、预留库存和低库存阈值；商品编辑允许调整实物库存，保存调整流水，拒绝调整到预留库存以下。
- 商品详情提供评价摘要和分页读取；本次不提供评价提交，待订单完成校验和订单明细模型实现后再建设评价写入。
- 为商品、分类和库存管理操作保存必要的管理员操作记录。本次不建设完整库存作业、审计查询界面、购物车、订单、轮播图或公告管理。

## Capabilities

### New Capabilities

- `fruit-catalog`：两级分类与商品/SKU 管理、图片、推荐、公开浏览搜索、详情、生命周期规则和买家收藏。
- `inventory-control`：本阶段 SKU 库存基础、商品编辑中的实物库存调整和调整流水；完整出入库与盘点工作流后续实现。
- `product-reviews`：本阶段商品评价摘要、分页读取及空状态；评价提交与订单模块衔接，当前不开放写入口。
- `platform-administration`：本阶段商品、分类及库存变更的管理员操作记录；日志查询和其他领域审计后续实现。

### Modified Capabilities

无。`openspec-cn list --specs` 当前未发现主规范；上述路径沿用 `fresh-fruit-ecommerce-platform` 变更中的能力名称，本变更只规定本次已确认的阶段范围，不宣称完成整体平台能力，也不修改旧变更。

## Impact

- 前端：更新首页、管理员布局、个人中心导航和路由；增加商品列表、详情、收藏、后台商品列表/编辑及分类管理页面和对应 API 类型。
- 后端：增加 catalog、inventory、review 和必要审计持久化逻辑，继续沿用 controller/service/mapper 分层及 `ApiResponse`；匿名只读商品接口与 BUYER/ADMIN 接口明确隔离。
- 数据库：在现有 V1/V2 之后添加 Flyway 迁移，创建分类、商品、SKU、图片、收藏、SKU 库存、库存流水、只读评价及管理员操作记录，并同步测试 schema。
- 存储：沿用本地文件存储方案，增加商品图片目录配置及受控图片读取，保留现有头像行为。
- 依赖：为真实 WebP 内容校验增加 Java ImageIO WebP 解码支持；分页若采用 MyBatis-Plus 插件，补齐其匹配的解析依赖，具体版本在实现时固定并验证。
- 验证：后端业务及权限集成测试、MySQL 迁移验证、前端类型检查/构建和商品管理到商城浏览的联调验收。
- 不引入新的云服务、Redis 或推荐算法服务；本轮只创建规划文件，全部产出物经用户审核并明确要求应用后才能编码。
